# 実データの品質確認

現在のGPTとWebアプリに同じPDF・所属・原文を入力し、結果を比較します。API料金が発生するので、まず3件程度で確認します。個人情報をGitHubのIssue・PR・テストデータへ貼り付けないでください。

| 対象 | 確認する点 |
| --- | --- |
| 正社員のPDF | 項目・罫線・資格欄・備考の文体、資料にない情報を生成しないこと |
| 契約社員のPDF | 所属が契約社員になり、単価に10万円を加算しないこと |
| BPのPDF＋元紹介文 | 原文65万円→提案75万円、原文が画面に残り、コピーには原価が混ざらないこと |
| チェック付き工程表 | 各丸印と見出しを目視照合し、チェックされた工程だけ・指定順に出ること |
| 工程表が空欄 | 本文に設計等の語があっても工程欄を要確認とすること |
| 不鮮明な丸印 | 推測で採用せず、確認メッセージが出ること |
| BP原文60〜70万円 | 自動確定せず元単価の入力を促し、65入力時に75万円になること |

API結果の `processEvidence` にはチェックのページ・業務名と位置を含めています。AIが示す根拠自体が正しいとは限らないため、PDF原本との目視照合が必要です。

実装時点では有料APIによる生成比較は未実施です。工程・備考の品質が元GPTに達しない場合は `lib/extraction.ts` の指示を調整し、必要ならモデル設定を変更します。価格の加算やフォーマットはプログラム側で固定しているため、モデルを変更しても維持されます。
