# 紹介文スタジオ

PDFのスキルシートから、既存GPTと同じ項目・罫線の要員紹介文を作るWebアプリです。初版は1人・1PDFずつ扱い、データベースや履歴保存を使わない構成です。

## できること

- 正社員／契約社員／BP（協力会社）をアップロード時に選択。
- OpenAI Responses APIでPDFの文字とページ画像を読み、項目を自動入力。
- BPの元紹介文を貼り付け、画面上にそのまま保持。元単価に100,000円を加算し、提案文には加算後だけを掲載。
- 65万円、650,000円、全角、65.5万円に対応。幅のある金額・時間単価・複数候補・不明金額は人が元の月額単価を指定。
- チェックを確認した工程だけを所定順で出力。工程の根拠（ページと該当位置）をAPI結果に含める。
- 紹介文の項目編集、コピー、テキスト保存。
- 未設定時も画面とBP計算は確認可能。架空のAI出力を返すデモモードはありません。

## Macで起動する

Node.js 22.18以降（24系推奨）とnpmを使用します。ターミナルでリポジトリの `web` に移動して実行します。

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

表示されたURL（通常 `http://127.0.0.1:5173/`）を開きます。画面・金額計算にはAPIキーは不要です。停止はターミナルで Control + C。

## PDFの自動入力を有効にする

API実行には料金がかかります。PDFのページ数やモデルで変わるため、初版では自動の大量実行をしません。まず1件の実データで品質と消費トークンを確認してください。

1. `.env.local` がない場合だけ `.env.example` をコピーします（既存設定は上書きしないでください）。
2. `.env.local` に以下を設定します。キー・パスワードをチャットやGitHubへ貼り付けないでください。

```dotenv
OPENAI_API_KEY=自分のAPIキー
OPENAI_MODEL=gpt-4.1
APP_ACCESS_PASSWORD=十分に長いランダムな利用パスワード
```

3. 開発サーバーを再起動します。
4. 画面でPDF・所属を選び、BPの場合は元紹介文を貼り付けます。
5. 利用パスワードを入力し、OpenAIへの送信と利用料の確認欄にチェックして「紹介文を作成」。
6. PDF原本と照合してからコピーします。

モデルは環境変数で変更できます。PDF画像入力とStructured Outputs（指定したデータ構造で回答する機能）の両方に対応したモデルを使用してください。`gpt-4.1` は設定例であり、現在利用中のGPTと同一モデル・同一品質を保証するものではありません。

## 元のGPTから引き継いだルール

- 氏名／所属／最寄／時期／単価／スキル6分類／資格（ある場合）／並行／備考の順。
- 資格は情報処理系のみ。備考に氏名を書かず、事実ベースで簡潔に紹介。
- 工程はチェックと列対応が明確な場合だけ採用し、本文から推測しない。
- 元指示の「並行あり」という見本値は、資料に根拠がなければ「要確認」。固定値を事実として補完しないための変更です。
- BPは表示名「BP（協力会社）」、コピー文の所属は元指示の「弊社協力会社」。

元紹介文は画面参照用で、顧客向けのコピー・ダウンロードには含めません。税・精算条件は原文と照合し、10万円加算後の扱いを確認してください。税計算・税変換はしません。

添付ZIPの参考PDFは抽出ルールを確認するために参照しました。参考PDF・候補者の個人情報は、この公開リポジトリに含めていません。人物の事実をプロンプトに埋め込まず、チェック位置を読むルールへ反映しています。参考PDFを毎回API送信する方式ではありません。

## 構成

- `app/page.tsx`：アップロード・所属選択・BP原文・編集・コピー画面
- `app/api/generate/route.ts`：生成APIの入口
- `lib/generate-handler.ts`：認証、入力検証、OpenAI連携、エラー処理
- `lib/extraction.ts`：既存GPTから移植した抽出ルールと回答チェック
- `lib/pricing.ts`：BP単価の判定と10万円加算
- `lib/introduction.ts`：元フォーマットの固定組み立て
- `tests/`：人工データによるテスト（有料APIを呼びません）

React／Vinextの画面とサーバーAPIを使用しています。Sites用のビルド構成は同梱されていますが、公開先の登録・公開は未実施です。GitHubへのコード保存だけではWebアプリは公開されません。

## データ・料金・共有運用

- サーバー側でAPIキーを管理。ブラウザには配信しません。
- 生成には共通の利用パスワードを必須とし、PDFは10MB、原文は20,000文字まで。
- PDFと元紹介文は生成時のみOpenAIへ送信。アプリのディスク・DB・ブラウザストレージに永続保存しません。
- OpenAIへのリクエストは `store: false`。これはOpenAI側のすべての保持・ログがゼロという意味ではありません。運用前に社内の個人情報の取り扱いと契約条件を確認してください。
- ログには処理ID、エラー種別、トークン数のみ記録。PDF、氏名、紹介文、キー、パスワードは記録しません。
- 送信中ボタンを無効化。HTTP 429/5xxのみ最大1回再試行し、結果が不明なタイムアウトを自動再実行しません。
- サーバー1プロセスにつき同時2件・1時間20件の簡易制限。再起動や複数サーバーをまたぐ厳密な料金上限・重複排除ではありません。多数ユーザー向けには共有の回数管理と個別認証が追加で必要です。
- 共通パスワードは小規模な社内利用向けです。社外を含む一般公開の前に個別ログインへ切り替えてください。外部共有時はHTTPS必須です。
- APIキーと公開先の設定、少数の実データによる比較確認を終えてから共有運用を開始します。
